# 加油站班次交接

- 行业：石油
- 技术栈：Vue3、Vite、TypeScript、Element Plus、Pinia
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 状态机单测：`npx vitest run`

数据保存在浏览器 localStorage（key：`gas-station-handover-v1`），刷新页面即模拟"电脑关机重开"，也可点顶栏【模拟关机重开】。

## 解决的问题

换班时交班人、接棒人同时处理油款、设备异常、顾客退款，责任与待办容易错乱。系统以**交接单状态机**为核心：

```
草稿(交班人处理) ──定稿──▶ 已定稿(逐项接收/退回) ──签收──▶ 已签收(责任转新班次)
     └─可作废（记录保留）
```

## 业务规则

1. **定稿前交班人继续处理**：草稿阶段只有交班人能登记/删除未结事项（油款 / 设备异常 / 顾客退款）。
2. **定稿成交接单**：确认后事项锁定，交班人停止修改，等待接棒人逐项处理。
3. **逐项接收或退回**：
   - 接收：该事项责任立即转到新班次，结果不可更改；
   - 退回：必须填原因，责任留在交班班次，交班人在【定稿/签收后】仍可登记闭环；
   - 全部逐项处理完才能整单签收。
4. **签收即终态**：接收项责任整体转新班次，单据不可重开。
5. **定稿后的补记 / 撤销 / 改派**：一律**重新发起一张修订单**，重走「定稿 → 逐项接收 → 签收」；原记录全部保留，仅追加"已撤销/已改派"标记与事件。进行中的同类修订单不能重复发起。
6. **关机重开续接**：未完成（草稿/已定稿）的单子原样恢复——已接收项不丢失、不重置、不能重开；打开应用顶部出现续接提示。
7. **旧班次没单也能补**：侧栏列出"缺交接单的班次"，可随时【补建】，单据标注"旧班次补建"；同班次只允许一张有效常规单。
8. **审计留痕**：每张单都有不可删除的事件流水（创建、定稿、接收、退回、闭环、签收、修订单关联等）。

## 目录

- `src/types.ts`：领域模型（交接单、事项、事件）
- `src/handover/service.ts`：交接单状态机（纯 TS，与 UI 解耦）
- `src/handover/store.ts`：localStorage 持久化、开机续接、预置数据（含一张接收了一半的早班单，打开即可体验续接）
- `src/handover/useHandover.ts`：Vue 组合层（自动存盘 + 操作反馈）
- `src/components/OrderDetail.vue` / `ItemRow.vue` / `AmendmentDialog.vue`：界面
- `src/handover/service.test.ts`：状态机规则单测（9 个用例）
